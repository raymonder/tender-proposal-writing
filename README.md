# tender-proposal-writing

版本：0.9

投标书 / RFP / 标书方案写作 skill，用于把招标文件、评分标准、需求矩阵、公司资料和产品能力整理成结构完整、回标清晰、语气稳健的投标方案文本。

## 能实现什么功能

- 根据招标文件或 RFP 拆出写作重点、评分点、硬性要求和风险边界。
- 组织技术方案、服务方案、实施方案、项目管理、运维支持、团队经验等章节。
- 把“我们有什么功能”改写成“针对招标方什么场景，我们如何回应并产生什么结果”。
- 按需求编号或条款编号逐条回标，方便评审查找。
- 标出不能乱承诺的内容，例如 SLA、第三方接口、上线时间、定制开发范围和数据迁移责任。
- 输出待确认事项，方便项目负责人、商务、法务或交付团队进一步确认。

## 怎么使用

在对话中提出投标方案或 RFP 回复任务即可，例如：

```text
用 $tender-proposal-writing 帮我根据这份 RFP 写一版技术方案。
```

```text
这份标书需要补实施计划、项目管理和售后服务章节，帮我写成正式投标语气。
```

```text
把这个需求矩阵整理成逐条响应表，并指出哪些地方需要商务或交付确认。
```

最好同时提供：

- 招标文件、RFP、评分标准、需求矩阵或 Q&A 澄清文件。
- 目标章节目录，或现有投标文件草稿。
- 公司、产品、案例、团队、资质、服务承诺等我方资料。
- 已锁定边界，例如报价范围、交付周期、不可承诺事项、技术架构。
- 输出格式要求，例如 Markdown、Word、飞书文档或 PPT 讲稿。

## 推荐输出结构

- 项目理解：招标方目标、业务场景、现状挑战、成功标准。
- 总体方案：总体思路、方案架构、核心模块、端到端流程。
- 需求响应：按条款或模块逐项回应，说明满足方式、实现路径、证明材料。
- 实施计划：阶段、里程碑、交付物、双方职责、沟通机制。
- 项目管理：组织架构、角色分工、质量控制、进度控制、变更管理。
- 安全与运维：权限、审计、备份、应急、培训、售后服务。
- 经验与优势：相关案例、团队经验、差异化优势。
- 风险与待确认事项：关键风险、前置条件、需客户或内部确认的问题。

## 写作公式

核心句式：

```text
针对 [招标方场景/要求/风险]，
我方将通过 [方案动作/产品能力/服务机制]，
实现 [可验证结果/交付物/管理效果]。
```

示例：

```text
针对项目上线后多部门共同使用、权限边界复杂的问题，我方将通过角色分级、操作审计和关键流程审批机制，确保不同岗位仅访问其职责范围内的数据，并为后续追溯和管理复盘保留完整记录。
```

## 主要限制

- 不替代法务、商务、报价或最终投标授权审批。
- 没有招标文件或评分标准时，只能先写投标草案，不能声称完全响应。
- 对第三方接口、数据迁移、SLA、上线日期、驻场安排等内容，应以项目负责人确认口径为准。
- 如果需求只能部分满足，应写清替代方案和边界，不能包装成完全满足。
- 本 skill 主要负责正式投标文本组织；产品功能的细节叙事可配合 `scenario-product-spec` 使用。

## 维护建议

- 把常见章节范例持续补充到 `SKILL.md` 或后续 `references/` 文件。
- 每次真实投标后，把“评审最关心但草稿漏掉的点”沉淀成检查项。
- 保持 skill 聚焦写作流程和风险边界，不要把具体客户机密资料写进公开仓库。
